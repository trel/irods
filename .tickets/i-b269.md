# Improve parser error recovery

Skip to next statement/rule instead of aborting entire parse on error


## Notes

**2026-01-11T03:34:49Z**

## Design: Multi-Error Recovery

### Current Error Handling
```c
#define CHECK_ERROR \
    if(context->error!=0) { \
        break;  // <-- stops all parsing
    }
```

### Target: Statement-Level Recovery
After parsing one statement/rule, if error encountered:
1. Collect error message
2. Reset context->error = 0
3. Skip to next sync point (`;` or `}`)
4. Continue parsing next statement

### Sync Points
- Rule boundary (after `}`)
- Statement end (`;`)
- Action block (between `{` and `}`)

### Implementation Strategy
1. Add `recoverToSync(Pointer *e, ParserContext *pc)` function
   - Skips tokens until `;`, `}`, or EOF
   - Resets context->error = 0
2. Wrap rule/action parsing in try-catch-like pattern
   ```c
   NT(Rule);
   if (context->error != 0) {
       generateAndAddErrMsg(...);
       recoverToSync(e, context);
   }
   ```
3. Maintain error array in rError_t instead of first error only
4. Document in parser.hpp with ASCII diagrams

### Testing
- Multi-error rule file tests
- Error count verification
- Line number accuracy for each error
- Recovery doesn't skip valid statements
