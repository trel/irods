DESIGN: Macro/Template System

PROBLEM: iRODS rules duplicate common action sequences, making code hard to maintain.

SYNTAX:
template GetAndLog(key) {
    val = get(key);
    writeLine("stdout", "Got: " ++ val);
    val
}

Usage: result = GetAndLog(mykey);

PARAMETERS: Can be expressions, code blocks, type parameters (no explicit annotations initially)

TYPE SYSTEM:
- Template return type inferred from body
- Last expression is return value
- Type check: argument types compatible with parameter types
- Template type signature: (type(P1), type(P2)) → type(Body)

AST REPRESENTATION:
- N_TEMPLATE_DEF: template name, param list, body
- N_TEMPLATE_APPLICATION: template name, arguments

IMPLEMENTATION PHASES:
1. Parser: recognize template keyword, parse definitions, store in symbol table
2. Type inference: infer parameter types from usage, validate body types
3. Code generation: inline template body with parameter substitution
4. Advanced: higher-order templates (code blocks as params), variadic, recursion

SCOPE: Global templates available everywhere; local templates scoped to rule

COMPILATION: Inlining (default) vs call-through strategy based on size heuristic

EXAMPLES:
1. Simple: template Increment(x) { x + 1 }
2. Multiple statements: template LogAndReturn(key) { val = get(key); writeLine(...); val }
3. With blocks: template TryExecute(action, fallback) { try { action } catch { fallback } }
4. Recursive: template Factorial(n) { if (n <= 1) 1 else n * Factorial(n-1) }

PERF: Zero overhead with inlining, constant with call-through, cache specializations

BACKWARD COMPAT: New syntax, opt-in, no breaking changes
