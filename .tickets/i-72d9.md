# Parser Architecture Refactoring: Reduce Macro Coupling

## Current State
The parser uses heavy macro abstractions that obscure control flow and make maintenance difficult:
- BUILD_NODE, CASCADE, CHOICE_BEGIN/END macros define most parsing logic
- Error paths use CASCADE macro with implicit error handling
- Control flow is hidden in preprocessor transformations
- Debugging requires understanding ~150 lines of macro definitions
- Adding new syntax or error handling is error-prone

## Problems
1. **Readability**: Macro expansions hide what code actually does
2. **Debuggability**: Stepping through macros in debugger is difficult
3. **Error verification**: Hard to ensure all error paths clean up resources
4. **Extensibility**: Adding new syntax requires careful macro manipulation
5. **Testing**: Can't isolate parser functions without understanding macro expansion

## Goals
- Extract explicit functions from macro-based implementations
- Create parser combinator library for common patterns
- Modernize error handling without goto-based cleanup
- Enable comprehensive error recovery and multi-error collection
- Improve debuggability and testability

## Sub-tasks (Planning)
1. Analyze macro coupling and identify refactor points
2. Extract parser state machine from macros into explicit functions
3. Refactor BUILD_NODE macro to explicit node construction
4. Refactor error handling from cascade macros to explicit paths
5. Extract parser combinator library from macro patterns
6. Modernize parser error recovery with multi-error collection
7. Create parser debugging/tracing infrastructure

**Effort:** ~60-90 hours across 7 tasks
**Blocking:** Grammar evolution (i-d794) depends on refactored parser
