# Add column type metadata infrastructure for genQuery


## Notes

**2026-01-12T19:34:03Z**

## Existing Infrastructure Analysis

### Found in typing.cpp
1. **getColumnTypeFromSchema()** (lines 83-240)
   - Maps 80+ genQuery column names to types
   - Column categories:
     * ID columns (ZONE_ID, USER_ID, etc.) -> T_INT
     * Name columns (ZONE_NAME, COLL_NAME, etc.) -> T_STRING
     * Time columns (CREATE_TIME, MODIFY_TIME, etc.) -> T_INT
     * Size/count columns (DATA_SIZE, etc.) -> T_INT
     * Path columns (RESC_VAULT_PATH, DATA_PATH, etc.) -> T_STRING
     * Metadata columns (META_*_ATTR_*) -> T_STRING
   - Fallback to T_DYNAMIC for unknown columns

2. **extractColumnNamesFromQuery()** (lines 35-65)
   - Extracts column names from N_QUERY AST nodes
   - Returns List of column name strings

3. **createTupleTypeFromColumns()** (declared in typing.hpp)
   - Not yet fully examined

### Architecture
- Column metadata is hardcoded pattern matching
- No central registry file
- Types are created fresh each call via newSimpType()

### Design Decision
The current pattern-matching approach is pragmatic:
- No need for separate data file
- All ~80 common columns covered
- Falls back to T_DYNAMIC gracefully
- No performance cost (compile-time lookup)

### What's Missing (for full metadata infrastructure)
1. Caching mechanism for repeated lookups
2. getColumnTypeFromSchema() should return persistent types
3. Documentation of column type contracts
4. Extended typing for complex columns (e.g., list types)
5. Integration tests validating column type inference
