# Grammar Evolution: Add Modern Language Features and Safety Constraints

## Current State
The rule language has a limited set of constructs that lack modern safety features:
- No optional/nullable type support (workaround: use T_DYNAMIC)
- No pattern matching or destructuring
- No try/catch exception handling
- No optional chaining operator
- No tuple unpacking or decomposition
- No macro/template system for code reuse
- No type guard predicates

## Problems
1. **Null safety**: No way to express nullable types or safe null handling
2. **Error handling**: No structured exception mechanism (errors are implicit)
3. **Code duplication**: No macros or templates to reduce boilerplate
4. **Pattern safety**: Can't match on types to narrow scope safely
5. **Ergonomics**: Tuples and complex returns are tedious to use

## Goals
- Add modern constructs: optional chaining, pattern matching, try/catch
- Improve null safety with explicit nullable types
- Enable code reuse through macros/templates
- Support destructuring and tuple unpacking
- Implement type guard predicates for safe narrowing
- Maintain backward compatibility during transition

## Sub-tasks (Planning)
1. Design optional chaining operator (?. syntax)
2. Implement optional type syntax (@optional, @nonnull)
3. Add pattern matching construct for type checking
4. Implement destructuring assignment syntax
5. Add try/catch exception handling construct
6. Implement tuple unpacking and decomposition
7. Add macro/template system for code reuse
8. Design and implement type guard predicates

**Effort:** ~80-120 hours across 8 tasks
**Priority 3**: Long-term evolution, depends on parser refactoring (i-72d9)
**Blocks:** None, but enables modern policy coding patterns
**Risk:** Language design requires careful consideration of semantics
