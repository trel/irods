# Implement N_ATTR typing with type preservation


## Notes

**2026-01-12T19:37:28Z**

## N_ATTR Implementation Analysis

### Current State (typing.cpp, lines 1531-1546)
N_ATTR (attribute access) currently:
- Delegates to child type (subtrees[0], usually TK_COL)
- Returns the child's type directly
- No explicit column type lookup
- Falls to T_DYNAMIC if no child

### Attribute Access Examples
- result.COLL_NAME (accessing string column) → should be string
- result.DATA_SIZE (accessing int column) → should be int
- result.UNKNOWN (accessing unknown column) → should be union

### Current Gap
When iterating query results:
- Query result type: collection<tuple<string, int, string>>
- Accessing element: result[i].COLL_NAME should be string
- But N_ATTR doesn't explicitly type column access

### Implementation Needed
1. **Direct column lookup** - If TK_COL node contains column name
2. **Tuple element access** - If N_ATTR accesses tuple element
3. **Union narrowing** - Apply constraints to union types

### Key Issue
N_ATTR appears in:
- foreach loops: 'foreach (result in query_results)'
- Direct query iteration: 'for (row in queryOut)'
- Tuple destructuring: 'var.fieldname'

Without proper typing, these patterns lose type information.
